# เว็บไซต์ห้องเรียนดิจิทัล ครูเนติพงษ์

เว็บไซต์ส่วนตัวแบบ Static ที่ใช้ฐานข้อมูลกลาง Supabase โปรเจ็กต์ **Ban Hin Lad Attendance** ภายใต้แพ็กเกจ Free (ไม่มีการอัปเกรด)

## หน้าเว็บไซต์
- หน้าแรกแนะนำครู สาระการเรียนรู้ และบทเรียน
- หน้า **รายวิชา** ที่ผู้ดูแลเพิ่ม แก้ไข หรือซ่อนรายวิชาได้เอง พร้อมสื่อแยกตามวิชา
- คลังใบงาน PDF / DOCX / PNG / JPG หรือเชื่อมโยงไฟล์ HTTPS และมีตัวกรองตามรายวิชา
- ประกาศสำหรับนักเรียน
- หน้าเกี่ยวกับครู

## ระบบหลังบ้าน (ล็อกอิน Supabase Auth)
- ภาพรวมชั้นเรียน
- เช็คชื่อวันเรียน: มา / ขาด / สาย / ลาป่วย / ลากิจ
- เพิ่ม / แก้ไข / ลบนักเรียน (เห็นเฉพาะห้องที่ได้รับสิทธิ์)
- สร้างกิจกรรมประเมิน (ใบงาน / แบบทดสอบ / ชิ้นงาน / กิจกรรม) และเลือกว่ารายการนั้นอยู่รายวิชาใด
- บันทึกคะแนนรายคน, ข้อเสนอแนะ, ส่งออกไฟล์ CSV
- เฉพาะผู้ดูแล: **จัดการรายวิชา** (เพิ่ม / แก้ไข / ซ่อน / ลบ / จัดลำดับ), อัปโหลด/เผยแพร่ใบงาน, จัดการประกาศ, แก้ไขชื่อเว็บและแนะนำตัว

## การเข้าสู่ระบบผู้ดูแล
ฐานข้อมูลและบักเก็ตเก็บใบงานสร้างแล้วใน Supabase; มีบัญชีผู้ดูแล 1 บัญชีที่ได้รับสิทธิ์ Admin แล้วในช่วงตั้งค่าเริ่มต้น
หากจำรหัสผ่านไม่ได้ ให้ใช้ปุ่ม **ลืมรหัสผ่าน** ที่หน้าเข้าสู่ระบบ และตั้งค่า Authentication → URL Configuration ให้ตรงกับลิงก์ GitHub Pages

1. หากต้องการสร้างบัญชีครูเพิ่มเติม เข้า [Supabase Dashboard](https://supabase.com/dashboard/project/jddcjezawvpnlnhhnlbq/auth/users) ของโปรเจ็กต์
2. ไปที่ Authentication > Users > Add user สร้างบัญชีครูของเจ้าของเว็บไซต์ และเลือกยืนยันอีเมลตามกระบวนการของโรงเรียน
3. ไปที่ SQL Editor แล้วตั้งค่าให้บัญชีที่สร้างเป็นผู้ดูแล โดยแทนที่ `ADMIN_EMAIL_HERE` ด้วยอีเมลที่สร้างจริง:
   ```sql
   update public.profiles p
   set role='admin', full_name='ครูเนติพงษ์ มาตนาเรียง'
   from auth.users u
   where u.id=p.id and u.email='ADMIN_EMAIL_HERE';
   ```
4. เข้า [Authentication Settings](https://supabase.com/dashboard/project/jddcjezawvpnlnhhnlbq/auth/providers) และปิดการสมัครสมาชิกด้วยตนเอง (ถ้าไม่ต้องการให้บุคคลภายนอกสร้างบัญชี)
5. เปิดเว็บแล้วล็อกอินจากปุ่ม **เข้าสู่ระบบครู** จากนั้นเพิ่มห้องเรียน/จัดการครูที่ระบบเช็คชื่อเดิม `../online/` และกลับมาบันทึกข้อมูลในเว็บไซต์นี้
6. ทดลองด้วยรายชื่อนักเรียน **สมมติ** จนกว่าจะตรวจสอบ RLS, ความเป็นส่วนตัว, การสำรองข้อมูล และผู้มีสิทธิ์เข้าใช้งานครบถ้วน

**ห้ามใส่ service_role key / secret key หรือรหัสผ่านลงใน config.js หรือ GitHub** ที่เผยแพร่สาธารณะ

## ไฟล์และพื้นที่จัดเก็บ
- `teacher_site` ข้อมูลหน้าเว็บ
- `teacher_announcements` ประกาศเผยแพร่
- `teacher_subjects` รายวิชาและการแสดงผล (Admin เพิ่ม/แก้ไข/ซ่อนได้; ประชาชนเห็นเฉพาะรายวิชาที่เผยแพร่)
- `worksheets` รายการใบงานเผยแพร่/ฉบับร่าง และ `subject_id` ที่เชื่อมกับรายวิชา
- `assessments` รายการประเมิน (private) และ `subject_id` รายวิชาของแบบประเมิน
- `assessment_scores` คะแนนรายคน (private)
- `storage.buckets.teacher-worksheets` ไฟล์ใบงานสาธารณะ (บังคับสิทธิ์ upload/delete สำหรับ Admin)
- `school_classes`, `students`, `attendance`, `profiles`, `class_teachers` ใช้ฐานข้อมูลร่วมกับระบบเช็คชื่อเดิม

**คำเตือน:** ใบงานที่เผยแพร่เป็นไฟล์สาธารณะ ไม่เก็บชื่อ/เลขประจำตัว/ผลงานรายคนในพื้นที่นี้ คะแนนและการเช็คชื่อถูกจำกัดสิทธิ์ด้วย Supabase RLS

## การเผยแพร่ GitHub Pages
มีไฟล์ workflow GitHub Pages ที่ `.github/workflows/deploy-pages.yml`
ไปยัง GitHub repository Settings > Pages > เลือก Build and deployment: GitHub Actions
เปิด `https://netipongmatnariang-stack.github.io/-/teacher/` เมื่อ GitHub Pages deploy สำเร็จ
การมีไฟล์อยู่ใน GitHub ไม่ได้ยืนยันว่า URL สาธารณะทำงานแล้ว

## ข้อจำกัดปัจจุบัน
- การสร้างบัญชีครูผ่าน Supabase Dashboard เท่านั้น ไม่เปิดสมัครสมาชิกสาธารณะในเว็บไซต์
- เมนูตั้งค่าชั้นเรียนและการมอบหมายครูใช้ระบบเช็คชื่อเดิม
- ระบบนี้ยังไม่รับการส่งใบงานโดยนักเรียน (มีเฉพาะครูเผยแพร่ใบงาน)
- ไม่สร้างนักเรียนจริงหรือกำหนดรหัสผ่านให้ผู้ใช้โดยอัตโนมัติ
